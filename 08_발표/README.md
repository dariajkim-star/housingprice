# 발표 슬라이드

`presentation.html` — 프로젝트 전체를 14장으로 요약한 발표 자료.

## 사용법
- 파일을 브라우저로 열면 바로 실행된다 (별도 서버 불필요)
- **← →** 또는 **스페이스**: 슬라이드 이동
- **F**: 전체화면
- **Home / End**: 처음 / 마지막
- 화면 왼쪽 1/4 클릭 = 이전, 나머지 클릭 = 다음
- 브라우저 인쇄(Ctrl+P) → PDF 저장 시 슬라이드가 페이지 단위로 나뉜다

## 구성

| # | 슬라이드 | 내용 |
|---|---|---|
| 1 | 표지 | 프로젝트명 · 저장소 |
| 2 | 다루는 데이터 | 1,460건 · 16 feature · 감축 기준 |
| 3 | 7단계 파이프라인 | 단계 간 산출물 전달 관계 |
| 4 | ① 탐색적 분석 | 왜도 1.88→0.12 · 지역 3.4배 격차 |
| 5 | ② 다중공선성 | 3쌍 제거 · VIF 5.31→2.81 |
| 6 | ③ 회귀 모델 5종 | 오차막대가 겹친다는 점까지 서술 |
| 7 | **발견 ①** | 이상치 2건 = SaleCondition Partial |
| 8 | 성능 개선 | R² 0.808→0.904 · 개선폭의 92% |
| 9 | ④⑤ Power BI | 시각 개체 5종 + Key Influencers |
| 10 | **발견 ②** | CentralAir 7.21배는 교란 변수 |
| 11 | ⑥⑦ 대시보드 + LLM | 필터 상태 전달 입증 |
| 12 | 도구 간 교차 검증 | kNN만 어긋난 이유 |
| 13 | 시각화 원칙 | 색 언어 · 메시지형 제목 |
| 14 | 정리 | 회고 3항목 |

## 설계 의도
- 이미지는 각 과제 폴더의 **실제 생성 차트**를 상대경로로 참조 — 별도 복사본을 두지 않아 원본이 갱신되면 슬라이드도 함께 갱신된다
- 색·타이포는 프로젝트 전체 시각 규칙(회색 맥락 / 남색 강조 / 빨강 이상치)과 동일
- 발표 흐름은 **과제 순서**가 아니라 **논증 순서**로 배치했다:
  데이터 → 파이프라인 → 결과 → **왜 믿을 수 있는가(발견 2건)** → 검증 → 정리
